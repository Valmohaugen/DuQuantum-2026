## Actionable findings

### F01 — P1: the constructor returns circuits over the hard moment limit

Location: `solution.py:499–502`, mirrored in `solution.ipynb`, circuit construction cell.

The challenge refuses circuits above 1,750 moments. `create_dicke_state` schedules the circuit
and returns it without checking its depth. A valid 90-qubit Willow path, requested at weight 45,
produces **1,817 moments**. The circuit passes `Willow105.validate_circuit` and returns all 90
requested qubits.

This was reproduced both with just the path calibration and with the complete Willow metadata
(105 available qubits, 182 calibrated couplers), assigning CZ error 0.001 to the selected path
and 0.05 to other couplers. The full-topology case returned in 10.51 seconds, so this is a depth
violation, not a timeout or invalid routing example. The current large tests stop at `(60,30)`.

**Required correction:** enforce the inclusive limit before returning. Improve the schedule or
raise `NotImplementedError` when it exceeds 1,750, as permitted by the original challenge. Add
the 90-qubit case as a regression and apply the limit to both DD modes. This does not require
editing the original challenge notebook.

### F02 — P1: resumed benchmarks can silently use scores from different code or models

Location: `claude/scripts/noisy_benchmark.py:138–147,158–171,203–233`.

The checkpoint signature includes seeds, cases, detuning, shots, and the ideal-baseline flag.
It excludes the preparation implementation/configuration, scoring source, actual calibration
maps, Cirq/NumPy versions, and important `NoiseConfig` fields: T1, Tphi, gate durations,
realization count, and maximum correlator size.

After any of those inputs changes, the saved keys still match and the code skips recomputation.
A partial run can mix old and new scores, then mark the result `complete: true`. A bounded probe
replaced the noise configuration class entirely without changing the signature; the loader
still accepted the saved result.

**Required correction:** fingerprint all effective configurations, source/calibration content,
and relevant runtime versions, and persist that provenance in the results. Treat existing
unfingerprinted checkpoints as legacy data. Preserve the recorded run as historical evidence;
its JSON alone cannot prove which preparation/noise source generated it.

### F03 — P1: importing the Python solution launches checks and the benchmark

Location: `solution.py:562–604`, particularly the guard at line 586.

The purported direct-execution guard is:

```python
if globals().get("__file__", "").endswith("solution.py"):
```

It is also true during `import solution`. The file consequently runs all unguarded exactness and
bonus loops, then calls the noisy benchmark and analyzer and may open a plot. That introduces
substantial simulation and writes to benchmark outputs before an importer obtains the functions.
In a standalone judging environment, it also imports local `claude.scripts` tooling that is not
part of the permitted solution-library import surface.

The actual guard AST was executed with stubbed modules and an import-style namespace
(`__name__='solution'`). It called both `noisy_benchmark.main` and
`analyze_benchmark_results.main`. No actual full benchmark was launched by this probe.

**Required correction:** use `if __name__ == "__main__":` and guard all script-only checks and
benchmark/UI work. Ensure the exported submission imports without file writes or simulations
and requires only the allowed libraries. Add a bounded import-safety regression.

### F04 — P2: the solution entry point's shot setting does not control sampling

Location: `claude/scripts/noisy_benchmark.py:56,206,215,229` and `solution.py:593`.

`NoiseConfig.shots = SHOTS` binds the value when the class is defined. The solution entry point
changes `noisy_benchmark.SHOTS` after import, but every configuration constructor in `main`
omits `shots=`. Changing `BENCHMARK_SHOTS` therefore changes the log/signature while simulation
continues using the original 10,000 shots.

Verified with `SHOTS=37`: the signature reported 37 and all three intercepted DD/no-DD/ideal
configurations still had `cfg.shots == 10000`. Editing the standalone benchmark constant before
import does work; the bug concerns the runtime override used by `solution.py`.

**Required correction:** pass the effective shot count explicitly to every mode. Test the actual
configuration received by sampling, not just the saved signature.

### F05 — P2: the tutorial's detuning experiment conceals a real leakage mechanism

Location: `claude/scripts/build_tutorial.py:614–665`; tutorial cells 38–39.

The leakage plot passes `{}` for detuning, regardless of the slider value. The exercise then
concludes that detuning cannot change leakage because Z rotations preserve Hamming weight.
That conclusion does not hold for the modeled compiled circuit: individual native single-qubit
gates in a Givens decomposition need not conserve excitation number. A phase error between
those gates can change final populations even though the ideal composite gate conserves weight.

For the actual compiled `(N,n)=(4,2)` circuit, DD disabled, all calibrated Pauli/readout errors
zero, and `T1=Tphi=1e12` microseconds:

| Alternating qubit detuning | Probability outside weight 2 |
| --- | ---: |
| 0 kHz | `1.87195e-12` |
| ±25 kHz | `0.00224857` |
| ±50 kHz | `0.00898777` |

Also, `shot_seed` seeds both the detuning draws and measurement sampling in `score_instance`.
Changing it with detuning enabled does not isolate shot noise, contrary to the exercise wording.

**Required correction:** calculate plotted probabilities with the same detuning ensemble as the
displayed scores and correct the physical explanation. Separate noise-realization seeds from
shot seeds when demonstrating shot-noise variation. Regenerate the tutorial after changing its
generator; preserve the protected original notebook.

### F06 — P2: calibration pairs are not sorted canonically

Location: `claude/scripts/challenge_calibration.py:60–65`.

`device.qubit_pairs` contains frozensets in the installed Cirq version. Sorting those objects
uses subset comparison, not a total ordering of qubit endpoints. Equivalent metadata collections
constructed in another insertion order can therefore consume the seeded draws in another order.

Rebuilding the same collection as `frozenset(reversed(list(metadata.qubit_pairs)))` preserves
topology equality but changes the sorted iteration. At seed 1234 this changed four couplers in
the symmetric difference of selected maps and changed rates on 60 common couplers. Repeated
calls against the current unchanged metadata remain deterministic; the failure is canonical
reproducibility across equivalent metadata representations.

**Required correction:** canonicalize endpoints before sorting the outer sequence, for example
`sorted(tuple(sorted(pair)) for pair in device.qubit_pairs)`. Fingerprint generated calibration
content as part of F02. Similar unsorted metadata iteration in the other local fake-calibration
helpers should be reviewed when consolidating those generators.

### F07 — P2: a supported one-seed benchmark fails during plotting

Location: `claude/scripts/analyze_benchmark_results.py:136–137`.

The benchmark and text summary handle a single sample by reporting zero spread. The plotting
function calls `statistics.stdev` unconditionally. With `BENCHMARK_SEEDS=(1,)`, valid final
results and a text report are followed by `StatisticsError: stdev requires at least two data points`.

**Required correction:** use the same one-sample policy in the plot and text paths. Add a tiny
synthetic-result regression that does not require running a quantum simulation.

### F08 — P2 boundary case: undefined official scores can poison stored results

Location: `claude/scripts/noisy_benchmark.py:130,150–155,205–233`.

The original score can be infinite for perfectly balanced finite samples or NaN when no Z shots
have the requested weight. For example, exact balanced `D(2,1)` Z samples `[01,10]` and X samples
`[00,11]` give a zero denominator and `inf`; zero requested-subspace Z samples give `nan`.
The wrapper stores either value directly. Python's JSON encoder emits nonstandard
`Infinity`/`NaN`, and subsequent aggregates or winner comparisons can become invalid while
the result is still marked complete. All 240 existing recorded scores are finite.

**Required correction:** preserve the original scoring function, but define an explicit status
and diagnostic policy in its wrapper. Do not silently clamp valid infinite scores to an arbitrary
finite number. Use strict JSON serialization and avoid treating undefined scores as normal
completed finite measurements.

## Physics assessment

The recursion and Givens sign convention are consistent with the intended Dicke state.
Partition the weight-k strings by their final bit. There are `C(N-1,k-1)` strings ending in 1
and `C(N-1,k)` ending in 0, out of `C(N,k)` in total. Thus the branch amplitudes are
`sqrt(C(N-1,k-1)/C(N,k)) = sqrt(k/N)` and
`sqrt(C(N-1,k)/C(N,k)) = sqrt((N-k)/N)`. The line construction uses
`theta = acos(sqrt(r/m))`, so its retained and shifted amplitudes have exactly those values.
At `r=0` the all-zero branch is unchanged; at `r=m` the all-one branch is unchanged. At
`m=2,r=1` the split angle is pi/4 and produces the positive-amplitude Bell/Dicke state.

For the W tree, before serving a child the parent holds amplitude `sqrt(remaining/N)`. Sending
the fraction `sin(theta)=sqrt(child_size/remaining)` gives the child amplitude
`sqrt(child_size/N)` and leaves `sqrt((remaining-child_size)/N)` at the parent. Repeating this
leaves `1/sqrt(N)` on the parent and, recursively, on every descendant. A one-node subtree
retains its single share; a chain transfers the correct decreasing remainder. The complement
construction works because bitwise X maps every weight-k string bijectively to weight `N-k`.

The five-CZ multiplexed gate is correct on the reachable inputs used by this construction, as
the tests explicitly check. Its docstring should state that precondition more clearly:
it is not a general controlled-Givens gate on all eight computational basis inputs. In
particular, its control-1, target-00 input acquires a relative minus sign. Reuse outside the
reachable subspace needs a separate derivation. No error was found in its present use.

The full-unitary scheduling probes verify a stronger property than matching Z populations:
they test relative phases for arbitrary four-qubit inputs. The observed noiseless results do
not establish behavior at every large N; no dense state-vector simulation was attempted for
the large hardware cases.

Primary references consulted:

- [Bärtschi and Eidenbenz, Deterministic Preparation of Dicke States](https://arxiv.org/abs/1904.07358), especially the recursive decomposition and nearest-neighbor construction.
- [Official Cirq Givens definition](https://quantumai.google/reference/python/cirq/givens), also checked against the installed version's docstring.
- [Official CZ decomposition API](https://quantumai.google/reference/python/cirq/two_qubit_matrix_to_cz_operations), also checked against the installed signature/docstring.
- [Willow specification](https://quantumai.google/static/site-assets/downloads/willow-spec-sheet.pdf), including the 68 microsecond T1 figure used as one model input.

## Benchmark interpretation and efficiency

The recorded aggregates are DD `3.3131209479` and no-DD `3.4725894749`, a difference of
`-0.1594685271`. The displayed aggregate spreads near 6.046 are the standard deviations across
16 different per-case means, not uncertainty in this difference. Pairing each seed's averages
across cases gives a difference standard deviation of `0.145572386` and standard error
`0.0651019501`. Five seeds, two detuning realizations per seed, and one synthetic calibration
do not establish a hardware-wide DD preference. The model assumes maximum correlator size 4;
the supplied challenge does not fix that judging parameter. Comparing means instead of sums
does preserve ranking for the same fixed case set.

Analytical probes confirmed the benchmark's detuning units, pure-dephasing factor of two,
amplitude damping, readout confusion-matrix orientation, and bit ordering. A one-qubit noise
calculation matched the density matrix to `1.11e-16`. A current-code `(2,1)`, seed-1, DD result
exactly reproduced its saved score `4.079842825577622`.

The main efficiency opportunities are:

1. Build each case's layout/circuit once per preparation configuration and reuse it across seeds.
2. Compute each ideal case's probabilities once, then draw all shot-noise samples from them.
3. Replace the dense full-register Hadamard matrix multiplication with local tensor operations;
   the current dense `H @ rho @ H.conj().T` does cubic work in Hilbert-space dimension.
4. Treat density-matrix simulation's `4^N` memory growth explicitly before expanding the small
   default benchmark. State-vector checks and structural hardware checks serve different scales.
5. Improve path-search coverage separately from correctness. Some large generated calibration
   instances legitimately return `NotImplementedError`; the challenge allows this. A beam
   search failure does not prove that no path exists, so its error text should not imply a proof.

  establish current evidence through N=20 structurally, not permanent regression coverage.

  on pytest through that module. Consolidate calibration helpers in production support code.

  actual simulation-only behavior; flipping the flag does not implement a submission workflow.

  environment/lock file, and `jupyterlab` is absent from both requirements and the selected
  environment despite the README's launch command. No current package conflict was found.
- No tracked lint/type-check/pre-commit/CI configuration was found. Ruff's six default findings:
  one unused tutorial import, three tutorial setup imports after path setup, one lambda assignment
  in `tutorial_utils.py:147`, and the late `itertools` import at `solution.py:535`. These are
  style/structure findings, not six additional physics bugs.
- Several public helpers lack the requested complete type hints, assumptions, failure-mode
  documentation, and paper/equation references. Existing plan text claiming a derivation in the

- Prepare an explicit submission artifact and checklist: permitted imports, both entry points,
